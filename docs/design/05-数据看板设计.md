# 05 数据看板设计（v0.1 · 重点优化）

## 1. 目标

总管理员/影院运营查看：**总票房、电影票房、影院票房**，支持按时间段/影片/影院过滤，前端 ECharts 折线图展示趋势。

约束：仅 PostgreSQL，不接缓存/消息队列；查询必须快、口径必须准、重复事件不能重复累计。

## 2. 指标口径（先定口径，再写代码）

| 指标 | 定义 | 计算 |
| --- | --- | --- |
| 订单数 order_count | 支付成功的订单数 | 支付成功 +1，退款成功 -1 |
| 出票数 ticket_count | 支付成功的票数 | 支付成功 +N，退款成功 -N |
| 总票房 gross_cents | 支付成功订单的实付合计 | 支付成功 +paid_cents |
| 退款额 refund_cents | 退款成功金额合计 | 退款成功 +amount_cents |
| 净票房 net_cents | 总票房 - 退款额 | gross - refund |

> 说明：`daily_box_office` 是**冗余聚合**，`box_office_ledger` 是唯一事实；两者不一致即 bug，对账任务兜底重算。

## 3. 数据流与幂等

```mermaid
flowchart LR
    PAID[支付成功事务] --> L1[写 box_office_ledger<br/>UNIQUE(ORDER_PAID, order_no)]
    L1 --> D1[upsert daily_box_office]
    REFUND[退款成功事务] --> L2[写 box_office_ledger<br/>UNIQUE(ORDER_REFUND, refund_no)]
    L2 --> D2[upsert daily_box_office]
    T[对账任务 5min] --> R[按支付/退款流水重算 ledger 缺失项]
    R --> D1
```

- ledger 与业务状态迁移**同一事务**写入，天然幂等（业务状态机已保证只迁移一次）。
- 对账任务只补 ledger，不直接改 daily 表；daily 可由 ledger 全量重算。

## 4. 表设计（migrations002）

### box_office_ledger（只增，事实表）

| 字段 | 说明 |
| --- | --- |
| id | PK |
| biz_type | ORDER_PAID / ORDER_REFUND |
| biz_no | order_no / refund_no |
| stat_date | 统计日（UTC+8 自然日） |
| cinema_id / movie_id | 维度 |
| order_delta | 订单数 ±1 |
| ticket_delta | 票数 ±N |
| gross_delta | 票款 ±paid |
| refund_delta | 退款额 +amount |
| created_at | |

> `UNIQUE(biz_type, biz_no)`：同一业务事件只记一笔。

### daily_box_office（聚合表，读优化）

| 字段 | 说明 |
| --- | --- |
| stat_date / cinema_id / movie_id | UNIQUE 三元组 |
| order_count / ticket_count / gross_cents / refund_cents / net_cents | 汇总值 |
| updated_at | |

索引：`(stat_date, cinema_id, movie_id)` 唯一；查询按 `(stat_date)` 范围即可，数据量万行内。

## 5. 接口设计

### 趋势（折线图）

`GET /api/v1/dashboard/box-office?start_date=2026-08-01&end_date=2026-08-31&cinema_id=&movie_id=&granularity=day|week|month`

```json
{
  "series": [
    { "date": "2026-08-01", "gross_cents": 500000, "refund_cents": 0, "net_cents": 500000, "order_count": 50, "ticket_count": 80 }
  ]
}
```

实现：`SELECT date_trunc(:granularity, stat_date), SUM(...) FROM daily_box_office WHERE ... GROUP BY 1 ORDER BY 1`。

### 电影票房排行

`GET /api/v1/dashboard/box-office/by-movie?start_date=&end_date=`

```json
{ "items": [ { "movie_id": 9, "movie_title": "沙丘3", "gross_cents": 1200000, "net_cents": 1100000, "order_count": 120 } ] }
```

### 影院票房排行

`GET /api/v1/dashboard/box-office/by-cinema?start_date=&end_date=`

权限（已确认）：SUPER_ADMIN 看全部影院；影院管理员（CINEMA_ADMIN）只能看自己绑定的影院（按 admins.cinema_id 过滤）；FINANCE 保留扩展。

## 6. 前端（ECharts，深灰管理端）

1. 筛选器：时间范围（默认近 7 天）、影院、影片。
2. 主图：净票房/总票房双折线（克制金色主线，深灰图表表面）。
3. 副区：电影票房排行表格 + 影院排行。
4. 空态与 loading 状态按 design-system 统一。

## 7. 性能目标

- 看板接口 P95 < 300ms（只扫聚合表）。
- 支付/退款事务内 upsert 单行，对主链路无感知。
- 不做 Redis；若后续日数据超十万行再考虑物化视图/缓存。

## 8. 验收标准

- Given 支付成功 100 元，When 看板刷新，Then 总票房 +100、订单数 +1；
- Given 退款 30 元，When 看板刷新，Then 退款额 +30、净票房 -30、订单数 -1；
- Given 同一回调重复，When 处理，Then ledger 只记一笔（幂等）；
- Given 对账任务重算，When 与 daily 不一致，Then daily 被重建为一致；
- Given 按影片过滤，When 查询，Then 只含该影片场次数据。
