# 01 管理员模块设计（v0.1）

## 1. 范围

总管理员/影院管理员能力：影片上架下架、影厅与座位设置、场次排期、票价设置、关键操作审计。

## 2. 数据模型（复用 + 新增）

复用已有表：`movies`、`cinemas`、`halls`、`seats`、`show_sessions`。
新增表（migrations002）：`admins`、`roles`、`operation_logs`。

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| admins | 管理员 | username、password_hash、role_id、status |
| roles | RBAC | code(SUPER_ADMIN/CINEMA_ADMIN/FINANCE)、permissions_json |
| operation_logs | 审计 | admin_id、action、target_type/id、detail_json、ip |

`admins` 增加 `cinema_id`（可空）：SUPER_ADMIN 为空，CINEMA_ADMIN 绑定影院，数据按 cinema_id 过滤。

鉴权（已确认）：用户端/管理端统一 JWT；管理员登录返回 Admin JWT，中间件按角色校验。

## 3. 接口设计

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | /api/v1/admin/auth/login | 管理员登录，返回 JWT | 公开 |
| GET/POST/PATCH | /api/v1/admin/movies | 影片列表/新增/编辑 | OPERATOR+ |
| PATCH | /api/v1/admin/movies/{id}/status | 上架/下架 | OPERATOR+ |
| GET/POST/PATCH | /api/v1/admin/cinemas | 影院管理 | OPERATOR+ |
| GET/POST/PATCH | /api/v1/admin/halls | 影厅管理（含座位布局） | OPERATOR+ |
| GET/POST/PATCH | /api/v1/admin/sessions | 场次排期/改期/取消 | OPERATOR+ |
| PATCH | /api/v1/admin/sessions/{id}/price | 票价调整 | FINANCE+ |

> 管理接口统一挂 `AuthAdmin(roles...)` 中间件；CINEMA_ADMIN 的读写按 `admins.cinema_id` 限定自己的影院。

## 4. 关键规则

### 4.1 影片

- 下架不影响已开场次；有关联未开场次的影片禁止物理删除（软删除）。

### 4.2 影厅与座位

- `halls.seat_layout_json` 是前端渲染坐标（排/列/类型/不可用位）。
- `seats` 表是售票事实（可售座位），保存影厅时按 layout **diff 同步**：新增/禁用/恢复，不做全量重建（保留座位 ID 稳定，订单历史不断）。

### 4.3 场次排期

- 同一影厅时间不可重叠：应用层校验 + 数据库排他约束（`EXCLUDE USING gist (hall_id WITH =, tstzrange(start_time,end_time) WITH &&)`，需 btree_gist 扩展；课程降级方案：应用层查冲突 + 事务重试）。
- 开场前 30 分钟锁定场次：不可改价/取消（可配置）。
- 取消场次：同一事务释放全部 LOCKED 锁、关闭待支付订单（EXPIRED）。

### 4.4 票价

- `base_price_cents` 基础价 + `price_rules_json` 按座位类型覆盖（如 {"VIP":16000}）。
- 改价影响新订单；已创建订单金额快照不动。

## 5. 审计

改价、发券、取消场次、调账等动作写 `operation_logs`（变更前后 JSON）。审计日志不可由业务接口删除。

## 6. 验收标准

- Given 同影厅重叠时间，When 保存场次，Then 拒绝并提示冲突。
- Given 已开场次，When 改价，Then 拒绝（409）。
- Given 取消场次，When 完成，Then 座位锁全部释放、待支付订单转 EXPIRED。
- Given 管理员改价，When 完成，Then operation_logs 有完整前后值。
