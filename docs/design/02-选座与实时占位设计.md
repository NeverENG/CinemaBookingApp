# 02 选座与实时占位设计（v0.1）

## 1. 范围

选座页：场次座位图查询、实时占用状态、锁座倒计时、可视化交互（前端）。

## 2. 后端接口

### GET /api/v1/sessions/{id}/seats

响应：

```json
{
  "session": {
    "id": 10,
    "movie_title": "沙丘3",
    "hall_name": "1号厅",
    "start_time": "2026-09-01 19:00:00",
    "base_price_cents": 5000
  },
  "seats": [
    { "seat_id": 1, "row_no": 1, "col_no": 1, "seat_no": "A1", "type": "STANDARD", "status": "available" }
  ],
  "server_time": "2026-08-29 12:00:00"
}
```

### 占用状态判定（只读查询，最终以锁座事务为准）

| 条件 | status |
| --- | --- |
| seats.status = DISABLED | disabled |
| 存在 LOCKED 且未过期的锁 | locked |
| 存在 BOOKED 的锁 | booked |
| 其他 | available |

- 不返回锁/购票人信息，避免隐私与骚扰。
- 锁定人自己刷新时前端用本地「已选座位」高亮覆盖 locked。

## 3. 实时性方案（DB-only）

- 前端轮询：3~5 秒拉取一次座位图（课程规模足够）。
- 提交选座时服务端权威校验：部分唯一索引 + 事务，前端显示只是「乐观视图」。
- 锁座成功返回 `lock_token` 与 `expires_at`，前端倒计时；过期后服务端释放，刷新视图。

## 4. 前端交互（胶片灰 / 影院红用户端）

1. 座位图由 layout_json 渲染，不可用座位置灰。
2. 点击座位 → 本地暂选（高亮影院红描边）→ 提交「锁座并下单」。
3. 锁座成功后显示倒计时，倒计时结束自动刷新。
4. 冲突提示：他人已锁/已购 → 刷新后置灰 + toast。

## 5. 边界与异常

- 场次 CLOSED/CANCELED：接口返回 409，前端提示不可购。
- 锁过期与支付并发：以 DB 唯一索引为准，不产生超卖。
- 轮询失败：指数退避重试，不阻塞本地交互。
