## 1. 项目背景与动机

**市场现状**：高校/社区影院普遍依赖线下排队购票，信息不透明，选座靠人工；主流平台（猫眼/淘票票）在校园场景渗透有限且缺少与本地影厅的深度绑定。

**痛点分析**：
- 用户：看不到实时座位图，热门场次跑空；取票/付款流程割裂。
- 影院方：排片、票价、票房统计靠手工表格，营销手段（优惠券/会员）缺失。

**项目目标**：以课程项目为载体，交付一套「仅依赖数据库即可保证可靠性」的电影院订票闭环系统，重点打磨实时选座、订单直付、退款/积分、优惠券/会员四块核心能力。

## 2. 产品商业方案

- **产品定位**：面向校园/社区影院的轻量订票系统，低成本、可私有化部署。
- **核心功能**：影片/场次管理、实时选座锁座、订单直付（Mock 支付）、退款与积分扣回、优惠券、会员积分、票房数据大盘。
- **核心竞争力**：数据库级并发兜底（不超卖、不重复入账）、支付回调幂等、完整营销闭环。

## 3. 市场竞争分析

| 维度 | 猫眼/淘票票 | 本项目 |
| --- | --- | --- |
| 优势 | 票源广、生态强 | 轻量、可私有化、校园场景聚焦、数据库即可跑 |
| 劣势 | 抽佣高、与校园影院系统打通成本高 | 无真实支付渠道、无平台流量 |
| 机会 | — | 校内运营、课程演示、可扩展为智慧影院一体机 |
| 威胁 | 平台补贴价格战 | 学校自建系统或线下人工售票 |

## 4. 商业模式与收益

- 盈利模式（模拟）：票务服务费、会员订阅、广告位、数据增值服务。
- 财务指标（课程范围）：不追求真实营收；以「支付成功率、锁座成功率、回调幂等率、票房统计准确率」为验收指标。

## 5. 资源投入与风险预测

- 资源：1 名开发（全栈）为主，约 3~4 周；依赖 PostgreSQL、Docker 基础环境。
- 风险与应对：
  - 并发选座超卖 → 数据库唯一索引 + 条件更新兜底；
  - 重复支付/重复入账 → 唯一幂等键 + 流水对账；
  - 会员/积分数值膨胀 → 等级只按累计获得积分升级，积分仅单向消耗；
  - 无真实支付渠道 → 模拟支付网关 + 可替换接口。
